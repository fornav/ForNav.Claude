# ForNav.Claude — Claude Code plugins for FORNAV AL development

A self-hosted Claude Code plugin marketplace that adds FORNAV-specific skills to Claude Code sessions used for Business Central / AL extension work.

## Plugins

| Plugin | What it does |
|---|---|
| **fornav-al-reports** | Guidance, scaffolding, and code review for AL developers integrating with FORNAV reports — temp tables, layouts, report/email/e-invoicing events, and autogenerated-code rules. |
| **fornav-al-tools** | Development workflow tools — switching `app.json` dependencies between e4 development mode and normal release mode, extracting DataContract / layout JSON from FORNAV `.docx` files, translating a project via the ForNAV JSON round-trip, and pre-commit workflow hooks (translation + `_docs` reminders). |

---

## Prerequisites

- [Claude Code](https://claude.ai/code) CLI installed and authenticated
- Git available on `PATH` (needed for the marketplace `add` step)

---

## Installation

Run these three commands in any Claude Code session (desktop, VS Code extension, or CLI):

```
/plugin marketplace add https://github.com/fornav/ForNav.Claude
/plugin install fornav-al-reports@fornav-claude-plugins
/plugin install fornav-al-tools@fornav-claude-plugins
```

Installation is per-session. You only need to do this once per machine; the plugins persist across future sessions.

To initialise a **new BC/AL project** with the full setup (plugin enablement, AL MCP server, prerequisites, conventions), follow **[SETUP.md](SETUP.md)**.

## Skills reference

### `fornav-al-reports`

**Auto-triggers** when you are writing or reviewing AL code that integrates with FORNAV — temp tables, `OnFillTemporaryTable` subscribers, autogenerated report code, request page options, multiple built-in layouts, extending existing FORNAV reports with `reportextension` objects, email scenarios, or e-invoicing hooks.

**Invoke manually:**
```
/fornav-al-reports:fornav-al-reports
```

What it covers:
- Report AL file structure and autogenerated-code rules (what to edit, what not to touch)
- Report extensions — adding columns, request page fields, and additional layouts via `reportextension`; virtual DataItems for data the base report doesn't iterate; binding extension columns in the Designer by typing `DynamicsNavDataSet.<ColumnName>` directly
- `OnFillTemporaryTable` event subscriber pattern with worked example
- `UseTemporary` DataItem pattern for reports you own
- Scaffolding new integrations (picks up your repo's ID range and naming prefix)
- Reviewing existing code for common mistakes
- Layout activation priority (why a layout change doesn't seem to apply)
- Less-common events: email scenario mapping, e-invoicing, text/HTML splitters

---

### `swap-deps`

**Auto-triggers** when you ask to switch between ForNAV e4 development mode and release mode.

**Invoke manually:**
```
/fornav-al-tools:swap-deps
```

Reads `app.json` from the current directory, detects the current mode, and rewrites the `dependencies` array between:

- **e4 dev** — single dependency on `ForNAV Core Development e4` (`d6978c22-...`)
- **release** — three dependencies: Language Module + Core + Customizable Report Pack (all `8.2.0.0`)

---

### `extract-layout`

**Auto-triggers** when you ask to extract, inspect, or view the DataContract or layout JSON from a FORNAV `.docx` file, or when troubleshooting why a report field isn't appearing in a layout.

**Invoke manually:**
```
/fornav-al-tools:extract-layout
```

Give it a `.docx` path or an `.al` file that references one. It extracts `DataContract.json` and `Layout.json` next to the source file, then summarises the data items and fields the layout knows about.

---

### `translate`

**Auto-triggers** when you ask to translate an AL extension, fill in or update `.xlf` translations, or add a new language to a project's `Translations` folder.

**Invoke manually:**
```
/fornav-al-tools:translate
```

Uses the ForNAV cmdlet's **JSON** round-trip (`Invoke-ExportTranslationFromXlfToJson` / `Invoke-ImportTranslationFromJsonToXlf`) so Claude edits the translations directly instead of a human editing Excel: refreshes the `.g.xlf`, exports to JSON, fills the missing target-language values, and imports back to `translation-<locale>.xlf`. Requires `"TranslationFile"` in `app.json` features and Windows PowerShell 5.1 (the ForNAV DLL doesn't run under PowerShell 7).

---

### Pre-commit workflow hooks

**Automatic** once the plugin is installed — no manual invocation. Two `PreToolUse` hooks fire before any `git commit` and pause for confirmation, reminding you to:

- **Refresh translations** — run the `translate` skill if any AL captions/tooltips changed.
- **Update `_docs`** — reflect the latest changes in the end-user guides.

They only match `git commit` (via an `if: "Bash(git commit*)"` filter), so other commands are unaffected. Defined in `fornav-al-tools/hooks/hooks.json`.

**Enabling per project:** commit a `.claude/settings.json` that registers this marketplace and enables the plugin, so the hooks and skills come along on clone:

```json
{
  "extraKnownMarketplaces": {
    "fornav-claude-plugins": { "source": { "source": "github", "repo": "fornav/ForNav.Claude" } }
  },
  "enabledPlugins": { "fornav-al-tools@fornav-claude-plugins": true }
}
```
